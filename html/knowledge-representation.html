From text to RDF

A Linked Open Data project exploring the mythological figure of Tiresias across classical antiquity, early modern engravings, and 20th-century modernist literature. This page documents the workflow from TEI/XML text encoding to the XSLT to HTML transformation and the RDF graph rendering.

TEI Encoding

A curated selection of the English Wikipedia article on Tiresias was encoded according to the TEI P5 Guidelines. Passages were sampled according to their relevance to the research, focusing on the portions dealing with the selected elements. Omitted passages are explicitly marked with <gap reason="sampling">, so that the selection remains visible rather than silently hidden.

The <teiHeader> records the primary source, defines the entities mentioned in the selected text (persons, deities, places, literary and visual works, mythological events and concepts) and declares, in <listPrefixDef>, the vocabularies used in the project. Here's a (perhaps more readable) list of the vocabularies used:

  • CIDOC-CRM, for identifying relations among cultural objects and figures (P62_depicts, P129_is_about) and or for relating characters or objects to temporal entities (E7_Activity, E5_Event);
  • Schema.org for classes like VisualArtwork, which encororates nicely both paintings and engraving, as well as predicates like character or contentLocation;
  • Dublin Core for the predicate creator ;
  • DBpedia, useful both for classes like dbo:Play or WrittenWork, as well as a few predicates, which are all apt for different entities while still maintaining some semantic specificity;
  • Wikidata as object for predicate sameAs;
  • the local ontology.

Entity annotation and relations

Each entity receives a local identifier and, where available, is reconciled with external authority records (Wikidata, DBpedia) through @sameAs. In the body of the text names are marked with <persName>, <placeName> and <title>, while events such as the sex change or the dispute between Zeus and Hera are marked with <rs type="event"> around the whole passage that narrates them; that's because an event is expressed by a stretch of text, not by a single term. The two artworks are encoded as <figure> elements with a <graphic> pointing to Wikimedia Commons and a <figDesc> describing the image.

Semantic relations are recorded in <listRelation>, where @active, @name and @passive correspond respectively to the subject, predicate and object later used by the TEI-to-RDF transformation. A simplified example of the encoding pattern is shown below.

<person xml:id="tiresias" sameAs="http://www.wikidata.org/entity/Q656881" role="prophet"> <persName>Tiresias</persName> <persName type="alternative" xml:lang="grc">Τειρεσίας</persName> <occupation>Blind prophet of Apollo</occupation> </person> <relation active="#tiresias" name="schema:workLocation" passive="#thebes"/> <relation active="#tiresias" name="tir:hasGift" passive="#prophecy"/> <relation active="#tiresias" name="tir:prophesiedAbout" passive="#narcissus"/>

TEI to HTML

The encoded TEI sample is rendered as a human-readable edition through an XSLT stylesheet (transformation.xsl). Structural divisions become HTML sections, and the encoding description in the TEI header is turned into a short colophon.

Each element keeps a distinct visual treatment. Persons, places and works are marked red and linked to their correspondent Wikidata entry; On the other hand events, since they span throughout whole sentences, receive a light background tint instead, and hovering over them shows the event they refer to.

Since we're dealing with a myth, it is not uncommon to have multiple versions of a story. The origin of the version told is preserved through explanatory notes that appear at the bottom of the page. Figures show the image in the text column with their caption in the margin, and sampling gaps remain visible in the output.

TEI to RDF

The same TEI document is the source of the RDF graph. Before the transformation, the classes and properties used in the header were collected in a small OWL ontology, so that every predicate in the graph is documented.

Ontology

TiresiasOntology reuses established vocabularies wherever possible: CIDOC CRM for events and their participants, places and temporal order; the DBpedia Ontology and Schema.org for mythological figures, deities, places and creative works; Dublin Core for authorship; the Europeana Data Model and SKOS for generic links and concepts. Each term is documented with rdfs:isDefinedBy, and a few subclass links connect the vocabularies to each other (for example, dbo:MythologicalFigure ⊑ dbo:FictionalCharacter and schema:VisualArtwork ⊑ schema:CreativeWork).

Only five properties are local: tir:hasGift, tir:prophesiedAbout, tir:illustrates, tir:resultsIn and tir:isPreconditionedBy. The first four are declared as subproperties of edm:isRelatedTo; tir:isPreconditionedBy is a subproperty of crm:P120i_occurs_after, because a precondition always comes first, so the temporal order between the dispute and the transformation can be inferred rather than stated. Since Tiresias is a mythological figure while Hera and Zeus are deities, properties such as crm:P11_had_participant and crm:P62_depicts take a union of classes as their range instead of an invented common superclass.

Transformation script

A Python script based on RDFLib and lxml (to_rdf.py) parses tiresias.xml and converts the semantic information in the header into RDF triples. Prefixed names are expanded exactly as TEI specifies, using the @matchPattern and @replacementPattern of each <prefixDef>, and the same prefixes are bound in the output, so dbo:, crm: or tir: appear in the Turtle file as they do in the TEI.

Local identifiers such as #tiresias or #thebes become URIs in a resource namespace kept separate from the ontology namespace. Each <relation> becomes one triple; attributes holding several values (for example passive="#hera #zeus") are split into separate triples, and symmetric relations expressed with @mutual are written in both directions. The @sameAs values become owl:sameAs statements linking the graph to Wikidata and DBpedia, and labels are generated with their language tags (@en, @grc). The graph is serialised in Turtle as tiresias_graph.ttl and parsed again as a validation step.

RDF visualization

Together, the encoding, the ontology and the transformations translate a selected source text into an interoperable RDF representation. By connecting persons, deities, places, events and works through shared identifiers and explicit relations, the resulting graph makes visible how the figure of Tiresias links myth, early modern art and modernist poetry.
